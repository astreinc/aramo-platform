## Summary of actual implemented changes

Adds recruiter-owned Outlook calendar scheduling (real events with the Talent as an
attendee + a Teams online meeting) as a **separate opt-in capability** alongside the
pre-existing create-link-only Teams meeting. A new delegated Microsoft Graph calendar
port/adapter creates, reschedules, cancels, and reads the organizer's own
`/me/events` using an opt-in `Calendars.ReadWrite` scope set requested only on explicit
recruiter enable+reauth (send-only connections untouched). Scheduling is persisted in
the Communications domain (`CommunicationInteraction` channel=meeting) behind a durable
scheduling-operation ledger with claim-based idempotency, an exclusive mutation fence,
checked finalization, full request-identity binding, and a provider-verified
reconciliation path for uncertain outcomes. Backend only — no frontend (PR 1B).

## Known limitations & unresolved questions

- `transactionId` is a best-effort Graph provider-dedup guard, **not** a durable lookup key; uncertain outcomes surface for bounded reconciliation rather than blind re-create.
- Reconciliation is operator-triggered (`reconcileMeeting`); no background sweeper (out of PR 1A scope).
- No bidirectional Outlook→Aramo sync; reads are last-known synchronized state, never represented as guaranteed-live Outlook.
- No frontend (PR 1B — separate prototype-to-backend reconciliation decision).
- Deployment is **not** authorized; the capability ships dark relative to prod.
