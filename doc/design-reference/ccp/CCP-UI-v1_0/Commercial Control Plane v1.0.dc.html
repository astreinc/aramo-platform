Open questions

For the PO and Architect. The prototype takes the stated assumption for each.

ForQuestionPrototype assumes
POWhich chain governs policy activation and rollback?Finance → Owner.
PODo non-privileged role changes (e.g. granting Support admin) also need a distinct Platform owner?Yes, one chain for all role changes.
ArchitectBootstrap rule: does the maker count toward "two distinct humans", or must each step have its own approver plus a separate maker?Maker plus a distinct approver per step.
ArchitectWhen not bootstrapped, is creating a request also refused, or only approving?Creation allowed; approval returns 409 CCP_NOT_BOOTSTRAPPED.
ArchitectIf an approver loses a role after signing a step, is that signature voided?No; only future eligibility changes.
POCredits and discounts on self-service tenants: Stripe-side commands through maker-checker, or link-out only?Stripe-side commands (CR-1042) shown as "Sent to Stripe — awaiting confirmation".
POChain for an out-of-bounds support extension?Below-threshold chain (Finance only).
POIs the 90-day extension window rolling from each use, or a calendar quarter?Rolling.
POMoving tenants from a grandfathered version to a newer one: is that a bulk change request? Not designed.Out of scope; pinned until changed per tenant.
POCan an expired or rejected request be cloned and resubmitted?Not shown; a new request is created.
POShould commercial roles also get read access to tenants (needed to open Tenant › Commercial)?Yes, read-only tenant access.
ArchitectPolicy numbering starts at v1 in the brief; the prototype adds a retired pilot v0 to show a request created under a previous version.v0 pilot exists.
PODashboard commercial panel (open approvals, expiring commitments, past-due, reconciliation flags) — which phase?Deferred; not built.
