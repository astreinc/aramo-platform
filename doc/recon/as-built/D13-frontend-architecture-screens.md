## Summary

- **`aramo-home-web`** (`apps/home-web`) — the App Home on the tenant host root (`/`), "My preferences" (`/preferences`) and Organization Administration (`/org/*`, rendered from `libs/org-admin-web`). Authenticates as the `org` consumer (`apps/home-web/src/main.tsx:20`). 13 `.tsx` + 5 `.ts` git-tracked files.
- **`aramo-ats-web`** (`apps/ats-web`) — the recruiter console (recruiter surface + ATS-owned settings), now served under `/ats/` (`apps/ats-web/vite.config.ts:38` `base: '/ats/'`; router `basename` at `apps/ats-web/src/main.tsx:31`). 428 `.tsx` + 263 `.ts` files; still the largest FE by an order of magnitude.
- **`aramo-platform-web`** (`apps/platform-web`) — the platform-operator console (tenant provisioning/lifecycle + Sign panel, skill governance, Aramo default document templates + variable catalog, matching policy, Personal review queue + invites). 42 `.tsx` + 12 `.ts`.
- **`aramo-portal-web`** (`apps/portal-web`) — the talent-facing privacy portal (records, verified identity, disputes, notice, erasure). 21 `.tsx` + 5 `.ts`; HTTP-only against `/v1/portal`. Source unchanged since the old baseline except `vite.config.ts`.
- **`aramo-sign-web`** (`apps/sign-web`) — the one Aramo Sign application on the Sign host, split into **zones** decided from the URL before any other code loads (`apps/sign-web/src/main.tsx:26`, `apps/sign-web/src/zones.ts:15`): the **guest** signing zone (`/s/:token`, `/d/:token`, legacy `/?token=`) that imports no `@aramo/*` library, and the **workspace** zone (sender console, Personal workspace, inbox, signup, legal, report, account close) that boots `@aramo/fe-foundation` as the `sign` consumer (`apps/sign-web/src/workspace/boot.tsx:27`). 49 `.tsx` + 16 `.ts`.

- **`libs/document-templates-web`** (`scope:shared`) — the shared document-template UI (safe HTML renderer, block editor, preview/approve modals, RTR template detail + draft editor, `/v1/document-templates` client), consumed by org-admin-web and by ats-web's Send RTR modal (`libs/document-templates-web/src/index.ts:1`; `apps/ats-web/src/rtr/SendRtrModal.tsx:3`).
- **`platform-admin`** (`apps/platform-admin`) — **NOT a frontend**. Every SPA except the sign-web guest zone shares the same chassis: a Vite entry mounts `createRoot` inside a `<BrowserRouter>` wrapping an `<App>` (`apps/home-web/src/main.tsx:30`; `apps/ats-web/src/main.tsx:29`; `apps/platform-web/src/main.tsx:25`; `apps/portal-web/src/main.tsx:28`; `apps/sign-web/src/workspace/boot.tsx:30`) and consumes **`@aramo/fe-foundation`** (`libs/fe-foundation/src/index.ts:1`) for the API client, session/auth, consumer binding, scope-gating, the shared sign-in page, the multi-product shell (`AramoAppShell`/`AramoRail`/`AppSwitcher`), the product-availability client (`GET /v1/me/products`) and the Radix-based component primitives. The sign-web guest zone is the exception: it boots without a router and without any `@aramo/*` import (`apps/sign-web/src/guest/boot.tsx:11`), enforced by `apps/sign-web/src/zones.spec.ts:27`. `fe-foundation` itself carries **no `@aramo/*` import** (0 matches for `from '@aramo/` under `libs/fe-foundation/src` at 680907fc) and side-effect-imports its own token/font CSS (`libs/fe-foundation/src/index.ts:10`).

**Auth consumer per SPA.** Each SPA binds its auth-service consumer with `configureAuthConsumer` before the first session fetch: home-web `org` (`apps/home-web/src/main.tsx:20`), platform-web `platform` (`apps/platform-web/src/main.tsx:18`), portal-web `portal` (`apps/portal-web/src/main.tsx:21`), sign-web workspace `sign` (`apps/sign-web/src/workspace/boot.tsx:27`). ats-web makes no `configureAuthConsumer` call and runs on the foundation default `'recruiter'` (`libs/fe-foundation/src/auth/consumer.ts:19`). The API client stamps `X-Aramo-Consumer` with the configured consumer on every call (`libs/fe-foundation/src/api/client.ts:116`).

**Authorization is scopes-only at the routing boundary, plus server-side product/org projections.** The session payload carries `Session.scopes: string[]` (`libs/fe-foundation/src/auth/session.ts:23`); the FE mirror is `hasScope(session, scope)` (`libs/fe-foundation/src/auth/scopes.ts:20`) plus a `requireScope` axis on `RouteGuard`. An authenticated session missing a required scope renders `<ForbiddenState>` — never a login redirect (`libs/fe-foundation/src/auth/RouteGuard.tsx:56`). Two newer surfaces gate on server projections rather than scopes: home-web/org-admin-web read `org_access` (`admin`/`templates`/`none`) from `GET /v1/me/products` (`libs/fe-foundation/src/platform/products.ts:23`; `libs/org-admin-web/src/OrgAdminRoutes.tsx:49`), and the sign-web workspace reads `GET /v1/sign/sender/context` (`apps/sign-web/src/workspace/api.ts:378`) and redirects to the backend-chosen workspace (`apps/sign-web/src/workspace/App.tsx:155`).

The ats-web design system layers on top of the frozen `fe-foundation` primitives: `ui/index.ts` re-exports frozen-themed primitives and adds app-layer atoms (`apps/ats-web/src/ui/index.ts:14`; `Card`/`CardHead` now re-exported from the foundation `SurfaceCard` at `:49`); `main.tsx` imports `theme.css` → `ui.css` → `settings.css` **after** the `fe-foundation` barrel so the `:root` token re-map wins on equal specificity (`apps/ats-web/src/main.tsx:11`). home-web follows the same load-order contract (`apps/home-web/src/main.tsx:11`). A lint-enforced **raw-element guard (G1/R2)** bans raw `<button>/<input>/<select>/<textarea>/<dialog>` in `apps/**` non-spec code (`eslint.config.mjs:39`, `:46`, block at `:285`); it does not apply to `libs/**`.
